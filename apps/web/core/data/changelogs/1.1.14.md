# 🎉 v1.1.14 Changelog

## ✨ New Features

- **Built-in MCP Server (Desktop)**: The desktop app can now act as an MCP server, so AI clients such as Claude Code, Codex and Cursor can work with your saved connections. Turn it on in **Settings → MCP Server**. The endpoint shares the app's port (for example `http://127.0.0.1:29092/mcp`), uses Streamable HTTP and only accepts requests from your own computer.
- **MCP Sessions**: Create a session for each MCP client and choose which workspaces and connections it can reach, with **No access**, **Read only** or **Read & write** per workspace and per connection. Each session gets its own bearer token, hidden by default with an eye icon to reveal it, plus copy and regenerate actions.
- **Optional Auth Token**: A session can turn off **Require auth token** so local clients connect without an `Authorization` header. Only one session can work without a token at a time.
- **Ready-made Client Setup**: Each session has copy-ready setup for Claude Code (`claude mcp add`), Codex (`~/.codex/config.toml`) and Claude Desktop / Cursor (`mcp-remote`).
- **MCP Tools**: `list_connections`, `list_schemas`, `list_tables`, `describe_table`, `run_query` and `explain_query` for PostgreSQL, MySQL, MariaDB, SQLite and Oracle. Connection credentials are never sent to the client.

## 🔒 Security

- **Read-only Enforcement**: Read-only access is checked twice: the SQL is validated (single statement, no write keywords), then the database itself runs the query in a read-only transaction (`PRAGMA query_only` on SQLite) that is always rolled back.
- **Local-only Endpoint**: The MCP endpoint rejects requests from other machines and blocks DNS-rebinding by checking the `Host` and `Origin` headers. The MCP server is off by default.
