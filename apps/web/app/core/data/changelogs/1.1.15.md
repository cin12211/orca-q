# 🎉 v1.1.15 Changelog

## ✨ New Features

- **RabbitMQ Connections**: Connect to RabbitMQ 3.12+ through the Management HTTP API. Browse queues (arguments, effective policy, bindings, consumers, backlog drain estimate), exchanges, connections and channels, peek messages with requeue, and publish a test message.
- **Apache Kafka Connections**: Connect to Kafka 3.5+ with optional SASL PLAIN / SCRAM. Browse topics with partitions, offsets, size and config, read messages by partition from newest, oldest, an offset or a time without joining a group or committing, live tail, view consumer groups with lag per partition, and produce a test message.
- **RabbitMQ Instance Insights**: Overview with node alarms, backlog and message-rate sparklines, plus nodes, ports, channels, connections, policies, vhosts, limits and feature flags. Add, edit and delete virtual hosts and policies, set or clear vhost and user limits, enable feature flags, force-close connections and rename the cluster.
- **RabbitMQ Users & Permissions**: Create users, edit tags and password, set or clear permissions, topic permissions and user limits, and delete users. Available to `administrator` users.
- **RabbitMQ Definitions**: Export and import broker definitions from the Definitions panel.
- **Kafka Instance Insights**: Cluster overview in the Instance Insights tab.
- **MCP Broker Tools**: The built-in MCP server serves RabbitMQ and Kafka through read-only `rabbitmq_*` and `kafka_*` tools (overview, queues, exchanges, peek, users, policies, topics, read messages, consumer groups).

## 🔒 Security

- **Strict Mode for Broker Writes**: Publishing, producing and every RabbitMQ management change (vhosts, policies, limits, feature flags, connection close, cluster rename, users and permissions) asks for confirmation in Strict Mode. Deleting a vhost or a user needs its name typed.
- **No Destructive Broker Actions**: Broker features never delete messages, purge queues or reset offsets. MCP broker tools never write, whatever the session's access level.
- **Safe Self-Management**: The connected RabbitMQ user cannot delete itself or drop its own `administrator` tag.
