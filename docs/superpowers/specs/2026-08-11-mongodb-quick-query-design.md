# MongoDB Quick Query Design

## Goal

Add MongoDB as a connection type and make its collections browseable and editable through the existing Quick Query entry point. This first delivery deliberately excludes raw-query execution, ERD, relations, SQL-only structure tabs, backup, import, and export.

## Chosen approach

MongoDB receives its own NoSQL runtime based on the official `mongodb` Node driver. It must not be routed through Knex or the SQL query/table adapter factories. The UI shares the existing grid and mutation controls where their contracts remain valid, but switches to Mongo-specific data/query composables whenever the selected connection is MongoDB.

## Connection model

`DatabaseClientType.MONGODB` identifies the client type. A new MongoDB connection family/provider kind controls navigation and feature gating. The connection wizard accepts a URI or host, port (default `27017`), credentials, database, and SSL configuration. Health checks use a short-lived `MongoClient` ping and return the existing normalized connection errors.

## Metadata model

The selected Mongo database supplies one logical schema name. Its collections are exposed to the existing schema store as tables, with `_id` as the primary key. Field metadata is inferred from a bounded sample of documents; it is advisory only, because Mongo documents are schema-flexible. Nested values remain JSON cells in the shared AG Grid.

## Quick Query model

The Mongo API accepts collection, filter, sort, projection, limit, and skip and returns documents, total count, inferred fields, and query time. It validates filter JSON and converts `_id` values to `ObjectId` only on server-side, so malformed identifiers return a controlled 400 error.

The first UI pass supports refresh, offset pagination, single-column sort, the current filter-builder subset, advanced filter JSON, insert, `$set` update, and delete by `_id`. Safe mode previews a human-readable Mongo operation; it does not present SQL. SQL-only areas—relation preview, ERD, and structure tabs—are hidden for MongoDB.

## Safety and limits

All collection identifiers come from metadata or validated request input. Filter/operator parsing allows only the operator subset generated by the UI and advanced JSON filter. Query, mutation, and sampling operations use explicit timeouts and bounded batches. MongoDB operations use `_id` for mutation identity, never grid row offsets.
